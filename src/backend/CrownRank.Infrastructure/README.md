# Infrastructure wiring

Infrastructure provides EF Core repositories, SQLite as an initial relational provider, provider-neutral EF mappings, a local profile-image store, and a development mock gateway. Domain and Application contain no EF or SQLite references. An alternative SQL provider can be supplied through `AddCrownRankPersistence(options => options.Use...(...), imageDirectory)` after referencing that provider in the composition root.

The host must configure `AddCrownRankSqlite(connectionString, imageDirectory, developmentMockPayments: true)` only in a development environment; production must register a real `IPaymentGateway` and must not enable the mock. Call `AddCrownRankPolicies` with current legal versions and an administrator PBKDF2-SHA256 salt/hash from secrets. These are bootstrap credentials, not an admin session implementation. The Console/API will register Application services and decide how the administrator authenticates.

The initial SQLite EF migration is checked in under `Migrations`. Apply it with `dotnet ef database update --project src/backend/CrownRank.Infrastructure --startup-project src/backend/CrownRank.Infrastructure` after configuring `CROWNRANK_DESIGN_CONNECTION`, or call `Database.MigrateAsync` in a deployment step. Do not call `EnsureCreated` on persistent databases. The migration is SQLite-specific; generate a separate migrations assembly for another provider because EF migration column types are provider-specific.

The database schema has unique `(PaymentProvider, PaymentReference)` contribution and `(Provider, Reference)` attempt indexes, and concurrency tokens on attempt and entry status. Transaction conflicts must be retried/reconciled by a host using a fresh scope; a concurrency failure cannot be reported as a successful payment. Checkout starts in two saves, so a gateway outage can leave a pending attempt. A recovery use case and persistent payment-status workflow should be added before accepting real charges. Mock checkouts are process-local and must not be used for durable payment verification. Ranking deliberately rejects mixed currencies until a single supported ranking currency is configured.

Run `dotnet test src/backend/CrownRank.slnx` with the .NET 10 SDK after restoring packages. Integration tests exercise SQLite relational constraints and persistence; test the eventual production provider separately, including concurrent confirmation across independent contexts.
